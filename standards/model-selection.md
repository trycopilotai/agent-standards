# Model Selection

Choose a model according to the task's reasoning needs,
permitted data access, available capability, and the
operator's cost constraints. An explicit operator choice
takes precedence over a default allocation policy.

Separate deterministic execution with a known recipe from
work requiring judgment, such as design, debugging, review,
and synthesis. Measure the result rather than assuming that
a provider or model name guarantees quality.

Read live usage information before balancing subscription
capacity. Distinguish unavailable usage data from exhausted
capacity. Do not enter metered overage without the required
authorization.

Maintain a provider registry with data-access restrictions,
supported models, context limits, and reasoning controls.
Verify current capabilities through the actual provider; do
not carry stale model tables forward as facts.

For independent reviews, use distinct reviewers and honor
any required provider separation. Disclose a reviewer's
actual identity and limitations. A self-reported provider
label is not authenticated provider provenance.

Pass only the data the reviewer needs. A code-only provider
must not receive personal datasets, private financial
context, or unrelated operator records.
